# Changelog

All notable changes to `raxol_agent` are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [3.1.0] - 2026-11-14

### Changed

- **`raxol_agent` requires `raxol_agent_client_protocol ~> 0.1.0`, so the ACP
  agent is compiled from Hex.** `Raxol.Agent.ClientProtocol.StdioAgent`,
  `ClientProtocol.Turn` and `ClientProtocol.Permission` are now part of a Hex
  install, and `ClientProtocol.Serve.run/1` serves an editor instead of
  returning 1 with "this build has no ACP support". The `web3` and `fx` tools
  are still compiled only where `raxol_web3` is present, which a Hex install
  does not have.
- **The `:raxol_agent_client_protocol` application now starts with
  `raxol_agent`.** It starts two `Registry`s, two `DynamicSupervisor`s and one
  `Task.Supervisor` under `RaxolAgentClientProtocol.Supervisor`; it opens no
  files, ports or listeners. A project that already registers any of their
  names fails to boot: `Raxol.AgentClientProtocol.SessionRegistry`,
  `Raxol.AgentClientProtocol.Ext.Journal.WriterRegistry`,
  `Raxol.AgentClientProtocol.Ext.Journal.WriterSupervisor`,
  `Raxol.AgentClientProtocol.Ext.AttachPolicy.TaskSupervisor` and
  `Raxol.AgentClientProtocol.ConnectionsSupervisor`.
- **`mix acp.schema.verify` appears among the project's Mix tasks.** It
  belongs to `raxol_agent_client_protocol` and refuses to run outside that
  package's repository.

## [3.0.0] - 2026-11-14

**Breaking.** Requires `raxol`, `raxol_mcp` and `raxol_journal` 2.8 (`~> 2.8`).

- The session journal and the event contract (`Raxol.Agent.Journal*`,
  `Raxol.Agent.Contract`) moved to `raxol_journal`, under the same module
  names. `raxol_agent` 2.7.0 defines the same modules, so 2.7.0 must not be
  combined with `raxol_journal`. The journal changed on the way: `status/1`
  returns `{:damaged, offset}` (was `:damaged`), and `verify/1` is a new
  required callback of the `Raxol.Agent.Journal` behaviour. See the
  [runtime changelog](https://github.com/DROOdotFOO/raxol/blob/master/CHANGELOG.md).
- The coding harness, memory, self-improvement and the coding tools are
  removed, and so are the modules nothing called (see Removed).
- From Hex, the ACP agent (`Raxol.Agent.ClientProtocol.StdioAgent`, with
  `ClientProtocol.Turn` and `ClientProtocol.Permission`) and the `web3` and
  `fx` tools are not compiled: they need `raxol_agent_client_protocol` and
  `raxol_web3`, which are not on Hex.

### Added

- **`raxol acp --agent <app>[:<id>]`: a Raxol agent for ACP editors.** Each `session/new` starts the named app (one of `:mcp_spawnable_apps`) with its journal bound to the real path of the request's `cwd`. A prompt is one turn of the agent; its tool calls are announced with their arguments, and a call to a `sensitive` action asks through `session/request_permission`. With `:<id>` a later run continues the journal, one session per server process. See [Editor ACP](https://github.com/DROOdotFOO/raxol-agent/blob/main/docs/features/EDITOR_ACP.md).
- **`raxol_agent`: `Raxol.Agent.McpTools.start_owned/4` and `stop_owned/2`.** Start and stop an allowlisted app for another owner under the `agent_spawn` rules; the `agent_*` tools do not answer for such an agent.
- **`raxol_agent`: agents as MCP tools.** Under `raxol mcp` and `mix mcp.server`, `agent_spawn`, `agent_list`, `agent_ask`, `agent_status`, `agent_stop` and the resource `raxol://agent/<id>/journal` start and drive agents this server started, each with a private, locked journal kept per project root (`Raxol.Agent.McpTools`). `agent_spawn` is refused on Windows.
- **`raxol_agent`: `:mcp_spawnable_apps`, `:mcp_project_root`, `:mcp_exposed_agents`, `:mcp_tools`.** The apps `agent_spawn` may start (default: the reference counter), the project root a journal is bound to (default: the working directory), agents started elsewhere that the tools may also reach, and where the tools register (`true`, `false`, or unset for a node booted for MCP).
- **`raxol_agent`: agent turn contract and a reference agent.** `Comm.call(agent, {:acp_prompt, text, approver}, timeout)` asks a session for one turn, answered `{:ok, text, usage}`; `approver` (an arity-3 `:tool_authorizer`) authorizes that turn's tool calls and is consulted in the turn's own process (started with the new `Comm.run_turn/3`), never inline in `update/2`, so a blocked ask holds up only that turn. The session stands in as the caller, so `{:acp_cancel, ref}` kills the turn's process instead of dropping its reply, answers the prompt `{:error, :cancelled}`, and, sent with `Comm.call`, replies `:ok` only once that process is dead. A turn is also cancelled when its caller goes down or its `Comm.call` times out, so a prompt needs an explicit timeout: `Comm.call/2` refuses one with `{:error, :timeout_required}` without sending it (other messages keep the 5 s default). A prompt or call-form cancel sent with `Comm.send` (with or without `from:`) is handled like its `Comm.call` form, and a prompt envelope without a pid caller and a reference ref is dropped without reaching `update/2` or the logs. A turn whose process crashes or is killed answers `{:error, :turn_failed}`, and every turn of a standalone session whose agent goes down answers `{:error, :agent_down}` with its process stopped (the session knows its agent is down by its own monitor, so a forged `:DOWN` naming the agent's pid changes nothing); a turn that ends without its reply (cancelled or failed) reaches `update/2` as `{:acp_cancel, ref}`. The agent sees a ref the session made for the turn, never the caller's, so the caller's ref cancels a turn but cannot answer it, start its work or message its process; an inline `Comm.reply` while the turn's process runs kills that process first, and `update/2` sees the cancel. `{:error, :cancelled}` does not roll back a change the turn already sent to the agent. Turn failures are logged by shape (exception module or leading atom), never content. The session finds the turn a `:DOWN` belongs to without a scan, so many turns ending at once cost linear time. `Comm.call/4` takes `ref:` (a fresh reference) so a caller knows the ref to cancel; `Comm.send_turn/3` messages a running turn. `Raxol.Agent.Reference.Counter` answers the contract with `increment`, `get`, a sensitive `reset`, and `hold`, which blocks until `release` or a cancel, and applies a change only from a turn it still tracks (the ref is its only credential) and forgets a denied hold.
- **`raxol_agent`: `Raxol.Agent.Backend.Anthropic.Wire` (ADR-0042).** `Wire` is the pure Anthropic Messages codec moved out of `Raxol.Agent.Backend.HTTP`: `build_request/2` returns `{url, headers, body}` (system messages joined into `system`, `x-api-key` omitted when no key is set, a non-empty `:tools` list passed through), `parse_response/2` returns the text or `tool_use` response contract or the keys-only `{:error, marker}`, and `api_version/0` is the `anthropic-version` header. `Backend.HTTP` now builds and parses every Anthropic request through it, with identical requests and responses; the caller still resolves the `max_tokens` default (`AI_MAX_TOKENS`).
- **`raxol_agent`: Robinhood browser sign-in.** `Raxol.Agent.Auth.Flow.run(:robinhood, opts)` returns a `%Raxol.Agent.Auth.Credential{}`; it is a separate clause and NOT in `Flow.providers/0`, so ACP clients never offer it.
  - `Raxol.Agent.Auth.Robinhood` pins the issuer, authorization, token and registration endpoints and the resource. RFC 9728/8414 discovery is fetched and checked against the pins (`{:error, :metadata_mismatch}` on any difference); dynamic client registration must echo the exact redirect URI and the `none` auth method; the code exchange and `refresh/2` are form posts through the `:http_fn` seam (default Req with `redirect: false, retry: false`). Errors are a closed set such as `{:token_rejected, status, :invalid_grant}`, never a response body. `refresh/2` adopts the rotated refresh token. `expires_at` comes from `expires_in` and is `nil` when the server sends none.
  - `Raxol.Agent.Auth.Loopback.open/1` takes `host: :ip` (redirect URI `http://127.0.0.1:<port>/callback`); the default stays `localhost` for OpenRouter. The new `await/3` ends the wait only for a GET on the callback path whose `state` matches in constant time with no repeated parameter, requires `iss` to equal the issuer (`{:error, :iss_mismatch}`), and drops the provider's `error_description`. `await/2` is unchanged.
  - `Raxol.Agent.Auth.Credential`: `Inspect` redacts the access token, refresh token and `user_uuid`; there is no `Jason.Encoder`, only `dump/1`/`load/1` for the encrypted store.
- **`raxol_agent`: the `web3` and `fx` tools are wired into real sessions.** New `Raxol.Agent.Web3` reads `config :raxol_agent, :web3` (`router:` enables `web3`; `fx: [rpc_urls: ...]` plus a Sleuth key from `fx: [sleuth_api_key: ...]` or `RAXOL_SLEUTH_API_KEY` enables `fx`) and puts `:web3_router` / `:fx_source` into the console gateway's tool context. Unconfigured, nothing changes. The configuration is resolved once at boot and cached, so no context build re-reads it or raises. A bad setting refuses the `raxol_agent` boot with an `ArgumentError` that names the setting and its shape, never its value: a `:web3` or `fx:` that is not a keyword list; a `router:` that is not a `Raxol.Web3.Router` (a struct is named by its module, a keyword list as a list); `fx` with no Sleuth key (the error names the variable and, for a node started from a raxol shell or MCP server, points at its own `fx: [sleuth_api_key: ...]` first and mentions `pass: ["RAXOL_SLEUTH_API_KEY"]` only as global, since that hands the key to every child the parent spawns); or a key with a space or line break inside it (the error says where the key came from, never the key).
- **`raxol_agent`: the `fx` tool (ADR-0040).** FX market data with a peg verdict, served as the `fx` agent tool (`Raxol.Agent.Actions.FX`) over `raxol_web3`'s `Raxol.Web3.FX`.

### Changed

- **Breaking: `raxol_agent`: `Raxol.Agent.Contract.pump/2,3` is `Raxol.Agent.StreamPump.pump/2,3`, and the old name is gone.** Same arguments and results. `Raxol.Agent.Contract` is in `raxol_journal` and keeps only the event schema, its encoder, `sanitize_payload/1` and `evidence_status/1`.
- **`raxol_agent`: a cancelled turn is stopped, then killed.** Its process gets an exit signal with reason `:shutdown` and is killed only if still alive after `config :raxol_agent, :turn_cancel_grace_ms` (default 500); a monitor of a turn that ends within the grace sees `:shutdown`, not `:killed`.
- **Breaking: `raxol acp` no longer serves the coding agent.** `--backend`, `--model`, `--harness` and `HARBOR_ACP_REQUESTED_MODEL` are gone (an unknown argument exits 64); `session/load` is not offered (`loadSession: false`); the Terminal Auth method is not advertised; a `session/new` `cwd` that is not an existing directory named by an absolute path is refused. `Raxol.Agent.ClientProtocol.Permission.authorizer/2` announces every tool call with its arguments and must be built in the process that ends the turn, which closes the calls with `settle/3`. `Raxol.Agent.ClientProtocol.Budget` is held by the connection as a pid: `check/0`, `record/1` and `spent/0` give way to `begin_turn/1`, `record_usage/2` and `spent/1`, `start_link/1` takes the environment, and `RAXOL_MAX_TURNS` counts a turn when it starts, whatever its outcome.
- **`raxol_agent`: every prompt turn is bracketed in the journal.** A session journals `turn_started` and one of `turn_completed`, `turn_canceled` or `error` around each `{:acp_prompt, ...}` turn, under a turn id of its own.
- **`raxol_agent`: a derived session id ends in 12 hex digits, not an integer.** A session started without `:session_id` journals under `<base>-<12 hex>`.
- **`raxol_agent`: the modules ADR-0042 keeps no longer reach into the coding harness.** **Breaking** for `raxol_agent` users: no behaviour changes, but a documented public name of the published package moves, so direct callers must update. The shell and network gates `shell_allow/2`, `shell_jail_allow/1`, `network_allow/1`, `sandbox_allow/2` and `jailed?/1` move from `Raxol.Agent.Actions.Code` to the new `Raxol.Agent.Policy.Grants` (no alias left behind), and every caller (`Directive.Executor`, `Actions.{FX,Web3}`) asks there. `Raxol.Agent.Auth.Flow`'s default OpenRouter `:store_fn` is now `Raxol.Agent.Auth.OpenRouter.store_key/2` (the same `Setup.connect_key/3` call with the same 120 s 1Password budget), so `Flow` no longer aliases `Raxol.Agent.Setup`. ADR-0040 notes the moved FX gate.
- **`Raxol.MCP.AgentBridge` ships in `raxol_agent`, not `raxol_mcp`.** `actions_to_mcp_tools/2` is unchanged. `meta_tools/0` and its `agent.list`, `agent.send` and `agent.get_model` tools are removed: they drove `Raxol.Headless` sessions, which `raxol_list`, `raxol_send_key` and `raxol_get_model` serve. `raxol_mcp` is 2.8.0 and `raxol_agent` requires `raxol_mcp ~> 2.8`: `raxol_mcp` 2.7 defines the module too, and lacks `Raxol.MCP.TreeWalker.action_name?/1` and `clean_spec/2`, which the bridge calls. `raxol_agent` 2.7.0 does not define the module, so a project on `raxol_mcp` 2.8.0 and `raxol_agent` 2.7.0 has no `Raxol.MCP.AgentBridge`.
- **The `:raxol_agent` application starts `Raxol.Agent.Supervisor`.** `Raxol.Application` no longer starts `Raxol.Agent.Supervisor`; the `:raxol_agent` application starts it in every startup mode. Only `:full` changes: the supervisor was a child of `Raxol.Supervisor`, started before the MCP tree, and is now a child of `RaxolAgent.Supervisor`, started after `:raxol`. A node that loads `raxol_agent` without starting its application has no agent supervisor until it starts `Raxol.Agent.Supervisor` itself. In `:mcp` and `:full` the `agent_*` MCP tools register where they did: with `config :raxol_agent, :mcp_tools` unset, only on a node whose startup mode is `:mcp` (`raxol mcp`, `mix mcp.server`). A registry run in any other mode, or one a host passes to `Raxol.Agent.Supervisor.start_link/1`, now needs `mcp_tools: true`. `mcp_tools: true` now registers them in any mode that runs the MCP registry, `:full` included, and `false` in none. The setting is read once, when `Raxol.Agent.McpTools` first starts, so it belongs in `config/*.exs`. The tools answer to whatever `config :raxol, :mcp_authorizer` the node sets.

### Fixed

- **`raxol acp`: a server whose launcher died stops.** `Raxol.Agent.ClientProtocol.ParentWatch` built its default action and never called it, so the orphaned BEAM kept its agents and journal locks. It now calls `System.stop/1`; the `:on_orphan` option is replaced by `:stop`.
- **`raxol_agent` on Windows: a CRLF `SKILL.md` parses.** `Skill.parse/1` required LF after each `---` delimiter, so a `SKILL.md` saved with CRLF endings was `:missing_frontmatter`. `Skills.Store.view/3` now also refuses a drive-rooted path such as `/etc/passwd` on Windows (`:volumerelative`). A test parses a CRLF skill on every platform.
- **`raxol_agent`: `ThreadLog.Postgrex` range reads no longer come back empty.** The list query builder numbered the optional clauses and `LIMIT` independently, so `list_by_kind/4` with the default `to: :infinity` and `list/3` with a bounded `:to` both put two parameters on `$4`; Postgres rejected the statement and the error was returned as `{:ok, []}`. Placeholders are now numbered from the parameter list itself. A failed read in `list/3`, `list_by_kind/4` or `latest/2` is now logged with the operation, table and thread (their behaviour callbacks have no error channel, so the return values are unchanged).
- **`raxol_agent`: `ThreadLog.Postgrex` reads canonical event kinds in a fresh VM.** Rows were decoded with `String.to_existing_atom/1`, so reading a `tool_call`, `state_snapshot` or other canonical kind raised `ArgumentError` until some loaded module happened to name the atom. Canonical kinds now decode through a literal map built from the new `ThreadEvent.canonical_kinds/0`; a custom kind decodes to its atom if one exists and otherwise stays a string, without minting atoms. The `:integration` suite can now run (`postgrex` is a test-only dependency and tables are created one statement at a time); a regression test reads rows from a child VM that has not interned the kinds.
- **`raxol_agent`: reading `~/.raxol/providers.json` no longer depends on which modules are loaded.** The `op_ref`, `model` and `base_url` fields were turned into atoms with `String.to_existing_atom/1`, which raised when no loaded module had named them yet, so `Credentials.fetch/1`, `delete/1`, `put/2` and `load/0` could crash depending on load order. The fields are now literal atoms. A regression reads all three fields from a fresh BEAM after checking that none of the atoms exist there yet.
- **`raxol_agent`: `op` is looked up only on absolute `PATH` entries.** A relative entry (`bin`, `.`, an empty element) resolves against the BEAM's working directory, so a cloned repository could ship a `bin/op` that received every `op read` and `op item create`. `Credentials.op_status/0` now reports an `op` that cannot be executed (exit 126/127, or a failed spawn) as `:absent` rather than asking for `op signin`, and `run_executable/3` returns `{:error, :op_spawn_failed | {:op_spawn_failed, reason}}` instead of raising.
- **`raxol_agent`: `Conversation.Log` kept an empty subscriber set for every conversation ever subscribed to.** `unsubscribe/2` and a subscriber's `:DOWN` deleted the pid from the conversation's `MapSet` but kept the key, so the log's `subscribers` map grew by one entry per conversation id for the life of the log (and `unsubscribe/2` on a conversation never subscribed to added one). A conversation's entry is now removed when its last subscriber leaves. The new `log_test.exs` tests failed before the fix (four empty sets left after unsubscribes; the killed subscriber's conversation left as an empty set).
- **`raxol_agent`: `SessionStreamer` monitored its subscribers on every subscribe and never let go.** Duplicate subscribes and each subscribe/unsubscribe cycle added a monitor that lasted until the subscriber died, so a long-lived consumer cycling per-run sessions grew the streamer's monitor list without bound (3,000 after 1,000 cycles). It now keeps one monitor per subscriber pid and removes it when that pid leaves its last session.
- **Globs under a directory no longer read the directory's own name as pattern.** `Path.wildcard(Path.join(dir, "*.md"))` compiles `dir` too, so a directory named `app [v2]` matched nothing, `app{a,b}` matched `appa/` and `appb/` instead, and on Windows every `\` separator was an escape. The directory part is now escaped (`Raxol.Agent.Glob.under/3`). Affected: `Skills.Store` (skipped every skill under such a root).
- **A Hex install of `raxol_agent` took the consumer's own project as `:raxol`.** The `raxol_dep` helper made `raxol_dep(:raxol, "~> 2.7", "../..")` a path dep inside a consumer's `deps/raxol_agent` (a parent directory always exists). It now hands out the Hex form only for a publish (`HEX_BUILD=1`) and inside a Hex install, which Hex marks by unpacking `hex_metadata.config` beside `mix.exs`.

### Security

- **`raxol_agent`: spawned processes no longer get the TUI's terminal as stdin.** Every spawner in `raxol_agent` opened its port with `:in`, believing it gives the child `/dev/null`. On Unix it does not: erts skips the stdin `dup2` and the child inherits the BEAM's fd 0, which under the TUI is the user's tty. A shell directive's command could read keystrokes typed into the TUI and rewrite the terminal's modes; the same held for the `op` CLI, which prompted on the tty instead of using the desktop app. Shell spawners now prefix their script with `exec </dev/null`; `op` runs through the new `Raxol.Agent.SpawnedPort.spawn_spec/2`, which wraps it in `sh -c 'exec "$@" </dev/null'` with the executable expanded to an absolute path, removes `SHELLOPTS`, `BASHOPTS`, `PS4`, `BASH_ENV` and `ENV` from the wrapper's environment, and drops anything the wrapper prints before `exec` (bash-as-sh warns about an uninstalled `LC_ALL`, for one), so none of it can reach a secret `op read` returns. Unix ports no longer pass `:in`, so a spawner that loses its redirect hangs its stdin test on every host rather than only under a terminal. Windows keeps `:in`, where erts does open `NUL` for an input-only port.
- **`raxol_agent`: spawned processes no longer inherit raxol's secrets.** Every child raxol starts for a model or a third party got the node's whole environment, so a prompt-injected command in a session holding the `fx` tool could `printenv RAXOL_SLEUTH_API_KEY`. Directive commands now go through `Raxol.Core.ChildEnv.port_env/1`, which unsets `RAXOL_SLEUTH_API_KEY`, `RAXOL_SHARE_SECRET`, `RAXOL_SESSION_STREAM_TOKEN`, `RAXOL_WALLET_KEY` and `RAXOL_ACP_AGENT_PRIVATE_KEY` in the child unless the caller passes one explicitly. Provider API keys are not scrubbed, since a user's own commands may rely on them. This stops inheritance, not every read: a same-user process can still read the node's launch environment (`ps -E`, `/proc/<pid>/environ`).
- Requires, when present, `req ~> 0.6 and >= 0.6.1` (was `~> 0.5`) for CVE-2026-49755 (unbounded decompression of a response) and CVE-2026-49756 (multipart header injection).
